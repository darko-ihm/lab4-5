# ЛР №4-5. Реалізація симетричного шифрування з використанням AES

> Це **поради**, а не інструкція. Можливі неточності; перевіряйте офіційну документацію та політики.

## Вимоги
- Python 3.10+
- `pip install -r requirements.txt`

## Швидкий старт
```bash
python aes_cli.py key new --label default
python aes_cli.py enc --in data/sample.txt --out outputs/sample.enc --mode gcm --label default
python aes_cli.py dec --in outputs/sample.enc --out outputs/sample.dec --label default
python aes_cli.py bench --sizes 1MB 10MB --modes cbc gcm --repeat 3
python tamper_demo.py --file outputs/sample.enc  # навмисне псування і перевірка
```

## Структура
- `aes_cli.py` — CLI/REPL (encrypt/decrypt/bench/key management)
- `crypto_aes.py` — реалізація AES‑CBC+HMAC та AES‑GCM, формат контейнера
- `key_manager.py` — PBKDF2, salt, key‑id, запобігання повторному використанню
- `logger_setup.py` — JSON‑логер
- `benchmark.py` — заміри продуктивності, CSV/MD
- `tamper_demo.py` — імітація підміни шифртексту/тегу
- `config.py` — параметри за замовчуванням
- `data/` — вхідні дані; `logs/` — журнали; `outputs/` — результати

## Попередження безпеки
- Не використовуйте демо‑код у проді без аудиту.
- Не повторюйте nonce/IV із тим самим ключем.
- Не зберігайте «голі» ключі на диску.

### Висновки щодо порівняння режимів та безпеки:
1. **Продуктивність:** Режим **AES-GCM** виконується швидше, ніж **AES-CBC**, оскільки об'єднує процес шифрування та генерацію автентифікаційного тегу за один прохід (AEAD) і використовує апаратні інструкції процесора (AES-NI). У режимі CBC обчислення HMAC вимагає повторного проходу по всьому масиву даних.
2. **Цілісність та автентичність:** 
   - **GCM** забезпечує цілісність автоматично через тег автентифікації (16 байт).
   - **CBC** реалізує захист за схемою **Encrypt-then-MAC** (HMAC-SHA256), що повністю нівелює класичні атаки на паддинг (Padding Oracle).
3. **Результати тесту підміни (Tamper Demo):** Спроба модифікації навіть одного байта у зашифрованому файлі викликає помилку перевірки тегу (`InvalidTag` або розбіжність HMAC) та блокує розшифрування, гарантуючи захист від несанкціонованих змін.

Логи зберігаються у форматі JSON у директорії logs/. Для аудиту безпеки проводиться моніторинг подій з рівнем WARNING та ERROR. Часті повторення помилок валідації (InvalidTag або Signature mismatch) сигналізують про спроби модифікації файлів у каналі передачі або перебір паролів (brute-force). Організаційно рекомендується налаштувати сповіщення SIEM-системи при фіксації понад 3 таких помилок за хвилину.

Технічні: повний перехід на AES-GCM або ChaCha20-Poly1305 для виключення людського фактора при ручній реалізації Encrypt-then-MAC; зберігання майстер-паролів в апаратних модулях безпеки (HSM / TPM).

Організаційні: регламентація процедури ротації ключів (наприклад, кожні 90 днів або після досягнення ліміту зашифрованих терабайтів), запровадження принципу найменших привілеїв при доступі до сховища ключів keystore.json.
